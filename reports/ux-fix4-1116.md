# TTT-UX-FIX4 — launch UX fixes F4, F9, F10

Slice of `reports/ux-audit-1116.md` (@680792b). Branch `ttt-ux-fix4`, landed on
`main` straight-to-main. Three findings, three mechanisms, all behind the
existing quality gates.

## F4 — `prefers-color-scheme` fallback (no first-paint flash)

- `public/theme-init.js` — the pre-paint script now resolves
  `matchMedia("(prefers-color-scheme: dark)")` when the preferences blob has
  no valid saved `theme`, instead of hardcoding light. An explicit saved
  light/dark still wins; corrupted or blocked storage degrades to the OS
  answer, never to a crash.
- `src/hooks/useAppTheme.ts` — `getInitialTheme` applies the same fallback
  (saved pref → OS media query → the `data-theme` stamp → light), and a mount
  effect re-stamps `<html data-theme>` + the `theme-color` meta when the init
  script never ran (blocked, test DOM).
- Tests: `src/__tests__/themeInit.test.ts` executes the real script against a
  fake DOM (6 cases: saved dark/light vs OS, OS fallback both ways, corrupted
  storage, missing matchMedia); `src/hooks/useAppTheme.test.tsx` pins the hook
  side (4 cases).
- After-shots: `reports/ux-audit-1116/after/fix4-onboarding-welcome-osdark-{phone,desktop}.png`,
  `fix4-lobby-default-osdark-{phone,desktop}.png` — captured with
  `colorScheme: "dark"` emulation and an empty preferences blob;
  `documentElement.dataset.theme === "dark"` and the computed background is
  the dark gradient in both.

## F9 — synthesized game audio, gesture-gated, persisted mute

- `src/lib/sound.ts` — four WebAudio cues synthesised in code (no assets, so
  the bundle stays flat): `place` tok, `vanish` poof, `turn` tick,
  `win` rising triad. Short envelopes, peak gain ≤ 0.055. The context is
  created lazily and `armSoundUnlock()` resumes it on the first pointer/key
  gesture; `playSound` refuses to schedule while suspended so nothing bursts
  on unlock. Mute lives in the preferences blob (`soundMuted`), read fresh per
  cue — same store the reactions mute pattern established.
- `src/hooks/useGameSounds.ts` — diffs successive `GameState` snapshots:
  `place` on moveCount advance, `vanish` a beat behind it when a mark retired,
  `turn` when the turn lands on a human (the "AI answered, your move" cue;
  computer turns stay silent), `win` on null→winner. Turn-clock ticks produce
  identical play fields and cost a comparison, not a sound.
- Wired into every surface that runs a `GameState`: `App.tsx` (local),
  `onlineGameSurface.tsx`, `queuePlay.tsx` (warm-up), `practiceStep.tsx`
  (onboarding tutorial).
- Settings: `PreferencesSheet` gains a Sound row with a `Volume2`/`VolumeX`
  toggle (`aria-pressed`, action-label, `max-sm:min-h-11`), modelled on the
  reactions mute; unmuting plays a tick.
- i18n: `settings.sound`, `sound.mute`, `sound.unmute` in both `en.ts`/`es.ts`.
- Tests: `src/lib/sound.test.ts` (fake AudioContext: recipes, mute, suspend/
  resume, gesture unlock), `src/hooks/useGameSounds.test.tsx` (real
  `makeMove` sequences → exact cue calls), `preferences.test.ts` +
  `preferencesSheet.test.tsx` for the persisted toggle.
- After-shots: `fix4-lobby-settings-sound-{phone,desktop}.png` (the Sound row
  is the visible surface; the audio itself is covered by the unit suites).

## F10 — "Try {next} next" after beating Easy/Normal

- `playersPanel.tsx` — new optional `onTryNextDifficulty` prop. When the
  completed game is a vs-Computer win by the human side and the game's own
  `aiDifficulty` (the F578 creation tier, not live settings) is Easy or
  Normal, a secondary glass button offers the next tier: Easy→Normal,
  Normal→Hard, Hard→nothing. Surfaces without the flow (warm-up, online,
  vs Friend) omit the prop and render nothing.
- `App.tsx` — the handler persists `aiDifficulty` and calls
  `handleReset({ aiDifficulty: next })`; `useLocalGame.handleReset` now takes
  `Partial<LocalGameInput>` overrides so the new match is dealt AT the offered
  tier in the same commit (the persona re-draw reads the overridden input, so
  the new tier's name pool applies; a typed opponent name still survives).
- i18n: `game.tryNext` ("Try {difficulty} next" / "Probar {difficulty} a
  continuación") with locale-aware `getDifficultyLabel`.
- Tests: `playersPanel.test.tsx` (offer matrix: Easy→Normal, Normal→Hard,
  Hard/AI-win/non-vsComputer/no-handler → nothing), `useLocalGame.test.tsx`
  (one-shot override deals the new tier immediately).
- After-shots: `fix4-game-over-win-easy-{phone,desktop}.png` — real games
  played to a human win vs Easy through the UI; the button was visible at
  capture (the capture loop keys on it).
